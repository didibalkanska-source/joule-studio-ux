Scenario 2 — Manage Invoice Exceptions: PO / GR / Invoice Mismatch
Challenge
  • Invoices blocked due to 3-way match failure — price / quantity mismatch, duplicate invoices, missing PO
  • Delayed payments, early payment discounts missed, late payment penalties, supplier escalation, audit compliance issues
  • AP Clerk, supplier, procurement and warehouse spend a lot of time communicating to resolve exceptions
AI Execution
  • Detects the failure — receives AP Invoices with exceptions
  • Diagnoses root cause — not just "match failed" but why
  • Checks all relevant context — PO, GR, vendor delivery notes, previous invoices from this vendor
  • Classifies the exception — tolerance variance vs. genuine discrepancy vs. timing issue
  • Resolves or escalates — acts within policy, prepares everything for human if needed
Outcome
  • Reduce exception resolution time
  • Exceptions resolved without human involvement; exceptional cases require review and approval
  • Supplier communication, payment terms and audit compliance are met

Key Decisions & Clarifications
✅
Scope is blocked invoices onlyFocus is only on invoices already in S/4HANA Cloud with blocked status — not how the invoice enters the system (OCR, scan, Ariba, etc.).
✅
Standard invoice domain model in S/4HANA CloudAgent works with the standard invoice business object regardless of the incoming channel. No need to understand the architectural specifics of each channel.
✅
Routing logic via decision tables / routing rulesThresholds by amount, supplier, exception type — already exist in customer environments. Will be realized as skills in Joule Flow. Business conditions are expressed by the process owner; technical realization is handled by the platform.
✅
Flow is landscape-specific, not one-size-fits-allWhen the process owner expresses intent, the web agent creates the flow based on the customer's specific system landscape (S/4HANA Cloud only, S/4HANA + Ariba, etc.).
⏸
Agent-to-agent communication — out of TechEd scopeLong-term vision allows agent calling another agent, but not included in the current TechEd scope. Space should be left for it in future design.
⚠️
Governance cannot fall on the end userBusiness users don't know about company governance, security policies, or agent permissions. Not everything can be on the shoulders of the end user. Clear boundaries needed between what a business user, IT admin, and agent can do. Aligned with SAP Global AI Ethics Policy.

AI Product & Workflow Design Challenges — From Research
Silent Generation & Deployment States
Users left in extended silent states during workflow generation and deployment — unable to tell if the system is working, done, or has failed.
Users lack guidance and real-time status
No In Progress / Done / Failed signals
Chat window could display real-time generation status
Chat–Canvas Desync
The conversation panel and workflow canvas display divergent information — users cannot tell which surface represents the true state of their workflow.
Terminology not business-user focused
Better integration of Chat into Canvas, with possibility to customize chat window position / size
Technical Language in Business-Facing Output
Post-specification summaries, error messages, and deployment illustrations use technical language and non-SAP visual patterns that business users cannot parse.
Pro Code mindset → Business Users are excluded
Definition of Personas — Joule Studio adapts during onboarding ("I'm a business owner / I'm a developer")
Even before typing, user selects a profile so experience adapts
Natural language description of each step outcome — why it is used
Missing Workflow Interaction Primitives
Users lack basic controls (retry, next-step buttons, save affordances) at every workflow phase — forcing them to type when they'd expect to click.
Allow simple shortcuts and quick actions for users to be empowered into editing
Chat window quick actions (e.g. test this path, remove last added step)
Keyboard shortcuts to drill down and continue on the flow
Autonomous AI Without Checkpoints
The AI generates and progresses through workflow stages without waiting for user confirmation — leaving users unable to pause, redirect, or validate before continuing.
"Human in the Loop" — expert users prefer manual control in addition to AI usage
Chat should ask confirmation and explain in natural language what will be generated beforehand
AI flow should allow to review, validate and refine / edit
Post-Generation Inspection & Editability Gap
Once a workflow is generated, users cannot easily open, inspect, or edit it — blocking the verification step business users need to trust what was built.
PRD too long to review
Not enough notifications on errors
Drilldown to artifacts to review its data, logic, rules
Correlate Workflow with PRD & SPEC
