Agent Evaluations
Автор: Diogo, Andre · Последна актуализация: май 2026 · 12 минути четене
QA системата за AI агенти в Joule Studio — дефинираш очакваното поведение предварително и го валидираш автоматично. Design Time + Run Time flow.
Жизнен цикъл QA Design Time + Run Time EAC Scope

Overview

Offline Agent Evaluations е quality assurance pathway в SAP Build's AI agent development tooling. Rather than waiting until an agent is in production to discover failures, evaluations allow business users and developers to define expected agent behavior upfront — through structured test cases called scenarios — and validate that behavior systematically across runs.

The flow spans two phases: Design Time (where scenarios are authored and configured) and Run Time (where evaluations are executed and results are reviewed) — each producing progressively more precise evidence of agent quality.

⚠️ Due to technical limitations for Sapphire timing, evals can only be run after the agent being deployed. However, the scenarios are still generated in the IBD flow.

Concepts

StepArtifact ProducedPurpose
1. Scenarios Pre-generated test scenarios Joule produces an initial set of scenarios during agent design time, grounded in the agent's known tools and intended use cases. These form the baseline test suite before any evaluation is run.
3. Evaluation Configured evaluation ready to run The user reviews the available scenarios, adds or removes test cases, and triggers the evaluation run. Scenarios can be generated on demand via Joule at this point.
4. Eval Runs Evaluation history and performance trend Once evaluations are run, results are recorded in a table alongside a regression/progression chart. Evaluations have states: Draft, In Progress, Complete, and Canceled. Only one draft can exist at a time.
5. Eval Results Per-scenario results and KPI metrics Clicking a completed evaluation reveals the full results view: a KPI card summary and a breakdown of pass/fail status per scenario, covering tool validation, response quality, and rule compliance.
Design principle: Each evaluation phase gates the next. Scenarios must be defined before an evaluation can be run, and results are only surfaced once an evaluation is complete. This prevents underspecified test cases from producing misleading quality signals.

Двете фази

Фаза 1
Design Time
Сценариите се генерират автоматично от IBD flow веднага след създаване на агента. Достъпни са от Design tab в agent artifact. Потребителят може да ги редактира или добавя нови преди deployment.
Фаза 2
Run Time
След deployment сценариите стават изпълними. От Evaluations tab потребителят стартира evaluation run, преглежда резултатите и следи performance trend с течение на времето.

Дизайн принципи

Всяка фаза gate-ва следващата. Сценарии → Evaluation → Results. Не можеш да прескочиш стъпка — предотвратява underspecified test cases от производство на подвеждащи quality signals.
Потребителят review-ва, не строи от нулата. Автоматичното генериране на сценарии от IBD намалява friction значително. Joule прави тежкото вдигане.
Trust чрез transparency. KPI карти + per-scenario breakdown дават конкретни доказателства за качеството, не просто "работи / не работи".
Progressive disclosure. Empty state → history → results — всяко ниво разкрива повече детайл само когато е нужно.
