Joule Flow
SAP Build AI · Платформа за агентски workflows
Joule Flow е платформата на SAP за изграждане и изпълнение на агентски workflows — многостъпкови, event-driven процеси, в които AI агентите действат самостоятелно, извикват инструменти и включват хора само когато е необходимо.
Intent Based Development Agentic Workflow Human-in-the-Loop SAP Build AI

Какво е Joule Flow?

Joule Flow е агентски workflow engine, изграден върху SAP Build Process Automation. Позволява на разработчици и citizen developers да дефинират многостъпкови бизнес процеси чрез Intent Based Development (IBD) — описваш какво трябва да постигне workflow-ът, а Joule генерира техническата имплементация. Агентите работят самостоятелно, консумират SAP Domain Models и Events, и ескалират към хора чрез SAP Task Center (Joule Work) само когато политиката изисква човешко решение.

Ключови градивни елементи
🧠
Intent Based Development (IBD)
Разработчикът описва намерението на workflow-а на естествен език. Joule генерира техническия поток — тригер, стъпки, агенти, действия — без ръчно свързване на nodes.
⚡
Agent Task
Стъпка в workflow-а, която извиква AI агент — SAP LoB агент (напр. AP Invoice агент) или custom агент на клиента. Агентът анализира, извиква инструменти и връща резултат.
📋
Human Task
Когато агентът не може да реши самостоятелно, се създава задача в SAP Task Center. AP Clerk вижда пълния анализ и препоръката на агента — решението отнема ~90 секунди вместо 45 минути.
🔔
Events и тригери
Workflows стартират чрез SAP Event Mesh (напр. събитие за блокирана фактура) или по разписание. Domain Events позволяват реалновременна, реактивна автоматизация без polling.
⏱️
Boundary Events
Механизъм за спазване на SLA. Ако задача не е решена в срок, workflow-ът автоматично ескалира към AP Manager или team lead.
🔁
Substitution Rules
Одобряващите в workflow-а конфигурират правила за делегиране — ако AP Clerk отсъства, задачите автоматично се преразпределят. Управлява се на ниво workflow или solution чрез IAS роли.

Известяване
Script Task — JavaScript стъпка за предварителна обработка, подготвя данните преди агента да работи.
Agent Task — извиква LoB агент или custom агент чрез Agent Gateway. Връща класификация, препоръка, изготвен отговор.
Decision / RM — определя маршрута: автономна резолюция или ескалация към човек, на база доверие и прагове на политиката.
Actions / MCP — изпълнява промени в S/4HANA Cloud чрез SAP APIs, custom MCP сървъри или LoB MCP инструменти (напр. деблокиране на фактура).
Joule Studio 2.0 — управляван provisioning слой. Абстрахира настройката на tenant-а, за да се фокусират разработчиците върху логиката на workflow-а.
Ключови персони
Изграждащ
Citizen Developer
Използва Joule Flow с IBD — описва намерението, Joule генерира потока. Не изисква дълбоки технически познания. Фокусира се върху бизнес резултата, не върху детайлите на имплементацията.
Изграждащ
Pro Developer
Разширява и персонализира потоците с Script Tasks, custom агенти, MCP сървъри. Обработва сложни интеграции, трансформации на данни и edge cases извън IBD.
Оператор
Process Owner
Притежава бизнес процеса (напр. AP Invoice). Следи KPI-та, дефинира SLA, конфигурира ескалационни пътища. Използва Analytics дашборди. Не участва в ежедневната обработка на изключения.
Краен потребител
AP Clerk
Получава задачи в SAP Task Center когато агентът не може да реши самостоятелно. Вижда пълния анализ, основната причина и препоръката на агента. Взима финалното решение за одобрение или отказ.
Краен потребител
AP Manager
Ескалационна цел чрез Boundary Events при наближаване на SLA срокове. Има право на override. Получава Analytics и KPI доклади от слоя на Process Owner.
Платформа
Customer IT / Admin
Следи workflow инстанции, логове и задачи. Управлява deployment чрез Git интеграция, задава роли на ниво solution или workflow definition чрез IAS.
Технически концепции

Изпълнение на workflow

  • Автономна резолюция — агентът действа в рамките на праговете на политиката без човешки преглед. Не се създава Human Task.
  • Праг на доверие — ако увереността на агента е под прага, ескалира към Human Task вместо да действа.
  • Audit Trail — всяко решение на агента, извикване на инструмент и действие на човек се логва. Пълна проследимост за compliance.
  • Тест и деплой — разработчиците тестват потоците в sandbox, деплойват чрез Git, оторизират чрез IAS роли.

Интеграционен слой

  • SAP Domain Models — структурирани SAP бизнес обекти (Invoice, PO, GR), консумирани от агентите като контекст.
  • SAP Event Mesh — event bus, задействащ workflows в реално време при бизнес събития.
  • LoB MCP — Line of Business MCP сървъри, предоставящи SAP-специфични инструменти на агентите (напр. AP Invoice LoB агент).
  • Agent Gateway — инфраструктурен слой, маршрутизиращ извикванията на агентите. Критична зависимост за EAC TechEd доставката.
  • Task Management MCP — позволява на агента да създава задачи в SAP Task Center. Критична зависимост за HITL.
