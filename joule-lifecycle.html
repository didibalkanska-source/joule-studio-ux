Plan & Build
Създаване на агент с архитектурен и бизнес контекст, съобразен с организационната стратегия
Фаза 1
Intent-Based Development
Workflow, започващ с описание на бизнес резултат на естествен език. Joule Studio превежда описанието в PRD (Product Requirements Document), технически спецификации, agent logic и deployment артефакти.
PRD → SPEC → code
Iterative Track: от бизнес проблем → PRD → SPEC с вграден SAP контекст → генериран код. Grounding е "grounded in real business processes" и "aligned with enterprise architecture".
Process context
SAP Signavio допринася с process models и agent mining на design stage — реални процеси стават основа за агент логиката.
Architecture insights
SAP LeanIX допринася с архитектурен контекст на design time — агентите се проектират в рамките на съществуващия enterprise ландшафт.
Joule Studio Agent SDK
SDK вътре в Joule Studio, опростяващ разработката на агенти — предоставя готови паттерни и интеграции.
Solution versioning
Инструменти за collaboration и versioning, позволяващи enterprise екипи да build-ват, review-ват и итерират с SAP-managed Git service.
Value modeling
Инструменти, оценяващи очаквания бизнес impact преди deployment — обоснована инвестиция.
🚀
Discover & Provision
Богат agent inventory и deployment с guardrails и необходимия достъп
Фаза 2
Agent & MCP Registry
Inventory catalog за discoverable агенти и MCP сървъри — централизиран регистър за всички налични capabilities.
Deployment to Git
Пълното решение се версионира в Git за reviewable, repeatable и portable промени.
Approval gate
Push към GitHub и ръчно тригване на GitHub Actions workflow — умишлена approval стъпка преди production deployment.
Vercel integration
Позволява build и deploy на модерни front-end приложения директно от intent-based flow.
Deployment pipeline
GH Action package-ва source кода, вика Joule Studio API и deploy-ва агента в production runtime.
⚙️
Run & Scale
Изпълнение на прости и сложни агенти в напълно гъвкава и управлявана среда
Фаза 3
Joule Studio Runtime
Напълно управлявана execution среда на SAP Business AI Platform — SAP-managed, enterprise-grade runtime за production агенти.
Built-in gateways
Вградени конектори за data products, APIs, AI модели и agent-to-agent взаимодействия.
SAP Agent Gateway
Задължителен unified connectivity hub, координиращ agent-to-agent, agent-to-tool и agent-to-Joule трафик. Вж. Gateway entity за 6-те core capabilities и разграничението TRAP 13 vs MCP Gateway.
📊
Observe & Analyze
Превръщане на observable agent telemetry в actionable intelligence
Фаза 4
Performance monitoring
Непрекъснато проследяване на cost/usage сигнали и observability в реално време.
Lifecycle observability
Operations tooling с tracing, metrics и logging — пълна видимост за поведението на агента.
Advanced observability
Cost attribution, performance trends и anomaly detection — за проактивна оптимизация.
Deployment visibility
Deployment статусът се вижда директно в GitHub Actions. Администраторите виждат solution, deployments и observability данни в prod Engagement Layer.

Secure & Govern
Агентите действат в рамките на организационните политики — governance при точката на изпълнение
Фаза 5
SAP AI Agent Hub
Централното място за управление и governance на агенти в enterprise мащаб.
Agent Evals & Assessment

Admin-level governance
Role-based access, lifecycle policies и oversight от dev до production. "Governed and observed at scale."

Optimize & Decommission
Планиране за развиващи се нужди и максимизиране на impact
Фаза 6
Continuous optimization
Резултатите се "continuously optimized through performance intelligence" — данните от фаза 4 захранват тази фаза.
Guided transition support
Помага на клиенти и партньори да преминат към Joule Studio инкрементално, защитавайки предишните инвестиции.
Cross-cutting pattern
🔌
Extensibility
Agent Extensibility платформата координира 3 персони — действа над целия lifecycle
Cross-cutting
Unified Metadata Service (UMS) — централен registry за extension point дефиниции. Осигурява discoverability между LoB Developer, Partner Developer и runtime агента.
LoB Agent Developer
1
Make agent extensibleДекларира extensible части: skills, tools, hooks, fields.
2
Publish extension pointsДефинициите се публикуват в UMS за discoverability.
Partner Developer
3
Deploy extensionsРазгръща extensions в Extension Service, което регистрира metadata в UMS.
Running Agent (Runtime)
4
Retrieve extensionsЧете extension metadata от UMS за context-applicable extensions.
5
Create observabilityEmitва observability данни за extension usage и execution.
